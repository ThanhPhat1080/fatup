# Kế hoạch: mã hóa Két sắt phía client (E2EE)

> **Cho agent thực hiện:** dùng `superpowers:subagent-driven-development` (khuyên dùng) hoặc `superpowers:executing-plans`, làm lần lượt từng task. Mỗi bước là một checkbox (`- [ ]`).

**Mục tiêu:** file và metadata trong Két sắt được mã hóa trên máy (desktop, web) trước khi rời máy; mở két bằng PIN két 6 số, server đếm số lần sai và giữ một bí mật chỉ trả khi PIN đúng; có recovery key, thùng rác riêng của két, và chuyển các file két cũ sang dạng mã hóa.

**Kiến trúc:** lõi mã hóa viết một lần trong `shared/src/vault-crypto.ts` bằng WebCrypto (chạy được ở Electron main, trình duyệt, Worker). Worker thêm bảng `vault_keys`, các route `/vault/*` và luồng cất vào / lấy ra (`/files/:id/vault/in|out`), bản mã nằm ở R2 key `vault/<id>`. Phiên két (`desktop/src/vault-session.ts`, không import Node) dùng chung cho desktop và web; desktop chạy nó ở main process và phục vụ ảnh két qua scheme `fatup-vault://`; web chạy nó trong bộ nhớ trang và dùng `blob:` URL. Renderer dùng chung cho cả hai: trình thiết lập, cổng 6 số, màu vàng đồng, thùng rác của két.

**Tech stack:** Hono + D1 + R2 (vitest workers pool), Electron + React (renderer dùng chung với PWA), WebCrypto.

**Spec:** `docs/superpowers/specs/2026-11-17-vault-e2ee-design.md` (đọc mục 3, 4 và 7 trước khi làm bất kỳ task nào).

## Ràng buộc chung

- **Không byte rõ nào của mục két lên server.** Nội dung, thumbnail, `name`, `mime`, `kind`, `url`, tiêu đề liên kết chỉ đi lên dưới dạng bản mã (`enc_meta`, object `vault/<id>`). Mục đã mã hóa có `name = ''`, `mime = 'application/octet-stream'`, `kind = 'file'`, `url = NULL`.
- **`MK`, `DEK`, `S` không bao giờ:** tới renderer của desktop, ghi xuống đĩa, `localStorage`, IndexedDB, log, hay thông báo lỗi. Đóng két = bỏ mọi tham chiếu.
- **Không object rõ nào sót lại:** `vault/in/complete` chỉ ghi D1 sau khi `vault/<id>` đã có trên R2, rồi **mới** xóa `files/<id>` và `thumbs/<id>.jpg`. Chiều `out` làm ngược lại.
- **Bộ đếm sai trên server:** sai 1–4 → 403; lần 5 → khóa 1 phút; 6–9 → mỗi lần khóa 15 phút; lần 10 → `auth_hash`, `server_secret`, `wrapped_mk_pin` = NULL (`state = 'wiped'`). Đúng → về 0. Tăng bộ đếm bằng **một** câu `UPDATE … RETURNING` (không đọc-rồi-ghi). So sánh hash hằng thời gian.
- `GET /vault` **không bao giờ** trả `auth_hash`, `server_secret`, `rk_auth_hash`, `wrapped_mk_pin`, `wrapped_mk_recovery`.
- App cũ: khi `state ≠ 'none'`, `PUT /files/:id/vault` và `GET /files?vault=1` thiếu header `X-FatUp-Vault: 2` → `426 app_outdated`.
- Kích thước upload vào két so với `vaultCiphertextSize(MAX_FILE_SIZE)`, không phải `MAX_FILE_SIZE`.
- Chuỗi hiển thị có đủ `en` và `vi` (`desktop/src/renderer/src/lib/i18n.ts`). Không đổi gì ở Android.
- Màu két: token CSS mới `--vault` (vàng đồng) và `--vault-tint` (nền ngả vàng rất nhẹ), có bản dark mode; vạch đỏ dùng `--danger` sẵn có.
- Thứ tự nâng cấp: `npm run db:migrate:remote` (`0009`) **rồi** `npm run deploy`.

## Trọng tâm review

- Thử PIN offline: với mọi thứ API trả cho người chỉ có token (`GET /vault`, `GET /files?vault=1`, `/vault/recover` khi sai `rkAuth`), có kiểm tra được một PIN mà không gọi `/vault/unlock` không? Phải là **không**.
- Hai request `/vault/unlock` sai gửi song song không được đếm thành một.
- Ngắt giữa `vault/in` (sau PUT, trước complete; sau complete) không để lại object rõ và không mất file.
- Renderer desktop: grep IPC/preload, không có đường nào trả `MK`/`DEK`/`S`.
- Mục két trên web không xuất hiện trong IndexedDB của kho ảnh xem trước.
- `DELETE` một mục két → nằm ở thùng rác của két, **không** ở thùng rác thường; Hoàn tác đưa về két.
- File két cũ (chưa mã hóa) vẫn mở được trong lúc chuyển đổi, và được mã hóa tiếp sau khi bị ngắt.

### Task 2: Lõi mã hóa (`shared/src/vault-crypto.ts`)

**Model:** Sonnet (đụng logic dùng chung / bảo mật); `test-writer` của task này cũng dùng Sonnet.

**Files:**
- Create: `shared/src/vault-crypto.ts`
- Test: `desktop/test/vault-crypto.test.ts` (Node WebCrypto), và một bản rút gọn trong `web/src/vault-crypto.test.ts` để chắc chạy được trên môi trường web của vitest

**Interfaces** (mọi khóa là `CryptoKey` không xuất được, trừ khi ghi khác; dữ liệu qua mạng là base64):
- `derivePinKeys(pin, saltB64, iterations): Promise<{ authKey: string /* base64 */; wrapBase: Uint8Array }>`: PBKDF2-SHA256 → 64 byte → HKDF ra `authKey` (info `fatup-vault-auth`) và `wrapBase` (info `fatup-vault-wrap`)
- `kekFrom(wrapBase, serverSecretB64): Promise<CryptoKey>`: HKDF(`wrapBase ‖ S`, info `fatup-vault-kek`)
- `newMasterKey(): Promise<CryptoKey>` (extractable chỉ để bọc), `wrapKey(key, kek): Promise<string>`, `unwrapMasterKey(wrapped, kek): Promise<CryptoKey>` (trả key **không** extractable cho dùng hằng ngày; bản extractable chỉ giữ trong lúc đổi PIN / thiết lập)
- `newRecoveryKey(): string` (128 bit, base32 Crockford, nhóm 4 ký tự nối bằng `-`), `parseRecoveryKey(text): Uint8Array | null` (bỏ khoảng trắng/gạch, không phân biệt hoa thường, sai checksum → null: thêm 1 ký tự checksum cuối)
- `recoveryKeys(rk): Promise<{ rkAuth: string; rkKek: CryptoKey }>`
- `newSetup(pin, opts?: { iterations?: number }): Promise<{ request: VaultSetupRequest; recoveryKey: string; mk: CryptoKey }>`
- `newServerSecret(): string`, `randomSalt(): string`
- `newFileKey(): Promise<{ dek: CryptoKey; wrapped(mk): Promise<string> }>`, `unwrapFileKey(wrapped, mk): Promise<CryptoKey>`
- `encryptMeta(meta: VaultMeta, mk): Promise<string>`, `decryptMeta(encMeta, mk): Promise<VaultMeta>`
- `encryptBytes(plain: Uint8Array, dek): Promise<Uint8Array>`, `decryptBytes(cipher: Uint8Array, dek): Promise<Uint8Array>`
- `encryptStream(dek): TransformStream<Uint8Array, Uint8Array>`, `decryptStream(dek): TransformStream<Uint8Array, Uint8Array>` (gom theo `VAULT_CHUNK_SIZE`, định dạng `FUV1` như spec 4.2; AAD = chỉ số khối 4 byte ‖ cờ cuối 1 byte)
- Lỗi: `class VaultCryptoError extends Error { code: 'bad_format' | 'tampered' | 'truncated' }`

- [ ] **Bước 1:** test đỏ:
  - mã hóa rồi giải mã cho 0 byte, 1 byte, đúng 1 MiB, 1 MiB + 1, 3,5 MiB ngẫu nhiên → giống hệt; `encryptBytes(x).length === vaultCiphertextSize(x.length)`; stream và bytes cho ra kết quả giải mã được chéo nhau.
  - sửa 1 byte bất kỳ → `tampered`; đổi chỗ hai khối → `tampered`; cắt bỏ khối cuối → `truncated`; sai magic → `bad_format`.
  - `derivePinKeys` cùng PIN + salt → cùng `authKey`; khác PIN → khác; `authKey` không bằng bất kỳ phần nào của `wrapBase`.
  - thiết lập → bọc `MK` bằng KEK (PIN + S) và bằng `rkKek`; mở lại bằng cả hai đường cho cùng một khóa (so bằng cách giải mã một `encMeta`); sai `S` hoặc sai PIN → unwrap thất bại.
  - `parseRecoveryKey` chấp nhận chữ thường, khoảng trắng, thiếu gạch; sai một ký tự → null.
  - `encryptMeta`/`decryptMeta` giữ nguyên tên tiếng Việt và URL.
  - Dùng `iterations = 1000` trong test cho nhanh (tham số truyền vào).
- [ ] **Bước 2:** chạy test → FAIL.
- [ ] **Bước 3:** cài đặt. Nonce mỗi khối = nonce gốc 8 byte ‖ chỉ số khối 4 byte (big-endian). `encryptMeta` dùng nonce ngẫu nhiên 12 byte đặt trước bản mã.
- [ ] **Bước 4:** test desktop + web → PASS; typecheck.
- [ ] **Bước 5:** commit `feat(shared): vault crypto core (FUV1 chunked AES-GCM, key wrapping, recovery key)`.
